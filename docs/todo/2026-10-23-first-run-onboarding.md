# 최초 설치 온보딩 검토 및 반영 계획

> 구현 후 로컬 빌드·회귀 테스트·컨테이너 재생성, 기존 설치의 온보딩·5개 언어 화면 확인까지 완료했다. [최신 수행 결과와 미검증 범위](../complete/2026-10-23-local-onboarding-verification.md)를 참고한다. 아래 내용은 최초 계획 시점의 기록이다.

- 작성일: 2026-10-23
- 상태: 온보딩·5개 언어 코드 반영 / 빌드·테스트·실환경 검증 대기
- 범위: 설치 후 관리자 설정, 언어, 사용 목적별 연결 준비, 첫 작업 안내
- 이번 작업: 소스 검토와 실행 중인 localhost 서버의 공개 상태 API 조회, 계획 문서 작성

## 현재 구현과 부족한 부분

| 항목 | 확인한 구현 | 보완할 부분 |
| --- | --- | --- |
| 최초 관리자 설정 | `web/src/app/(auth)/setup/page.tsx`에서 설정 토큰과 비밀번호를 받아 기존 초기 설정 API 호출 | 성공 후 곧바로 `/function/tasks`로 이동하여 연결 안내가 없음 |
| 로그인 | `web/src/app/(auth)/login/page.tsx`에서 미설정 설치만 `/setup`으로 이동 | 환경 변수로 관리자 설정한 설치와 기존 설치에도 시작 안내 진입점 필요 |
| 빈 작업 목록 | `web/src/app/(main)/function/tasks/page.tsx`의 빈 상태 문구 | 준비 사항, 설정 이동, 첫 작업 안내 부족 |
| 언어 | 시스템 설정에 5개 언어와 서버 출력 언어 저장 기능 존재 | 설정 전 화면에서도 언어를 선택하고 로그인 후 설치 언어에 반영하는 흐름 필요 |
| 모델 | `/system/llm`에 프로파일 저장, 활성화, 연결 시험 존재 | 기본 모델 준비 여부 및 다음 단계로 이어지는 안내 없음 |
| MCP | `/system/mcp`에 서버 설정과 도구 새로고침 존재 | 사용 목적에 따른 선택 사항이라는 설명과 복귀 동선 필요 |
| API·소스 진단 | `/offensive/assessments`에 capabilities, catalog, 실행 화면 존재 | 서비스 설정 유무, 실제 접근, 개별 도구 사용 가능 여부를 분리해 안내 |
| Splunk | `/function/purple/sources`에 연결 저장 및 인증 시험 존재 | 로그 파일 방식과 선택 관계 안내, 인증 성공과 로그 접근 검증의 차이 표시 |
| 시작 안내 | 전용 onboarding/getting-started 화면과 통합 체크리스트 미발견 | 기존 기능을 연결하는 얇은 안내 화면 추가 |

## 확인된 판정상의 한계

- `server/server.go:health`는 서버 응답과 버전을 반환한다. DB·외부 연결 전체의 정상 상태를 의미하지 않는다.
- `server/server.go:getLLM`의 configured/key_set과 프로파일 존재 여부만으로 실제 모델 응답을 보장할 수 없다. 환경 변수에서 로드한 전역 모델도 고려한다.
- `server/offensive_reviews.go:offensiveCapabilities`의 runner_configured는 설정 존재 여부다. 서비스 응답 및 catalog의 개별 도구 availability를 별도로 확인해야 한다.
- `server/security_sources.go:testSecuritySource`는 관리 API 연결·인증 확인이며, 선택한 index의 로그·경보 읽기 성공까지 검증하지 않는다.
- `server/server.go:testLLM`과 `agent/provider.go:TestConnection`은 실제 모델 요청을 실행한다. 시험은 30초 제한, 1턴, 출력 상한 8192이며 저장된 실행용 max_tokens 전체를 재현하지 않는다. 따라서 결과는 연결 확인으로 표시한다.
- 모델 연결 시험은 현재 키가 비어 있으면 실패한다. 인증 없는 로컬 모델 지원을 이미 제공한다고 안내하지 않는다. 필요하면 별도 호환성 범위로 검토한다.

## 제안 사용자 흐름

1. 설치 문서에서 실행 환경·접속 주소·설정 토큰 위치를 안내한다. 웹 화면에서 Docker나 DB 설치를 자동 실행하지 않는다.
2. `/setup`에서 언어 선택 및 기존 관리자 설정을 수행한다. 기존 설정 토큰 검증, 재설정 방지, 오류 시 접근 차단을 보존한다.
3. 설정 성공 후 `/onboarding`으로 이동한다. 이미 관리자 설정을 마친 설치는 시스템 설정과 작업 목록에서 동일한 안내로 진입할 수 있다.
4. 사용 목적에 맞는 항목만 보여준다: AI 작업, API·소스 진단, 방어 검증·침해 조사. 목적 선택은 안내용이며 기존 기능 접근 권한을 바꾸지 않는다.
5. 기존 설정 화면에서 필요한 연결을 설정하고 시작 안내로 돌아온다. 설정 입력 화면을 복제하지 않는다.
6. 준비 요약에서 가능한 기능과 아직 확인하지 않은 연결을 안내한다. 사용자가 기존 생성 화면으로 이동하여 직접 첫 작업을 시작한다.

| 사용 목적 | 필요한 준비 | 선택 사항 |
| --- | --- | --- |
| AI 작업·AI 검토 | 실제 선택되는 모델 설정, 활성 모델 또는 기존 전역 설정 확인 | MCP, 검색, 알림 |
| API·소스 진단 | 진단 서비스 접근, 해당 도구 사용 가능, 사용자 대상 등록 | 후보 AI 검토를 사용할 때 모델 |
| 방어 검증·침해 조사 | 기능에 맞는 로그 파일 또는 Splunk 데이터 소스 | AI 조사에 모델, 자동 실행에 해당 실행 서비스 |

MCP·Splunk·검색·알림을 모든 사용자에게 필수로 요구하지 않는다. 샘플 데이터, 데모, AWS 실습은 추가하지 않는다.

## 단계별 구현 계획

### 1단계: 시작 안내와 진입 동선

- `web/src/app/(main)/onboarding/page.tsx` 신규: 기존 Card, Button, Badge, Alert와 번역 구조 사용.
- setup 성공 경로, 시스템 설정, 작업 목록 빈 상태에 진입점 추가. 기존 설치를 무조건 다른 화면으로 보내지 않는다.
- 기존 설정 페이지에 온보딩에서 들어온 경우에만 돌아가기 동선 제공. 반환 경로는 허용된 내부 경로로 제한한다.
- 기존 GET API에서 준비 상태를 읽고, 상태 조회 실패는 미설정이 아니라 확인 불가로 표시한다.
- 모델 프로파일 목록뿐 아니라 실제 전역 모델 설정도 반영한다. 원문 키나 키 힌트를 체크리스트·로그·브라우저 저장소에 복제하지 않는다.
- 숨김 등 UI 선호만 브라우저에 저장하고, 완료 여부는 현재 설치 설정에서 다시 판단한다. 설치 전체 완료 플래그나 새 테이블을 만들지 않는다.
- 인증 전 언어 선택은 브라우저 표시만 바꾼다. 인증 후 사용자가 선택을 확정할 때 기존 언어 저장 기능을 사용한다. 다른 브라우저 로그인만으로 설치 언어를 덮어쓰지 않는다.
- 5개 언어에 새 문구를 모두 추가한다. 사용자 입력·모델 응답·증거 원문은 번역하지 않는다.

### 2단계: 연결 확인과 사용 목적별 준비 상태

- 상태를 미설정 / 설정됨·미검증 / 연결 확인됨 / 실패 / 확인 불가로 구분한다. 필수 여부와 건너뛰기는 별도 속성으로 표시한다.
- 기존 모델 시험, MCP 새로고침, Splunk 시험을 재사용한다. 외부 요청·비용·도구 프로세스 실행 가능성을 버튼 주변에 설명하고 명시적인 사용자 클릭 시에만 실행한다.
- 자동 진입·새로고침·폴링으로 외부 연동 시험이나 진단을 실행하지 않는다. 진단 runner 접근 확인도 명시적 동작으로 제한한다.
- 연결 결과의 확인 시각과 확인한 범위를 표시한다. 설정 변경 시 이전 결과를 무효화하고, 변경 여부를 확신할 수 없는 재방문에서는 미검증으로 돌아간다. 시험 이력 영구 저장용 스키마는 추가하지 않는다.
- 모델 시험 성공을 실제 장시간 작업 성공으로 표시하지 않는다. Splunk 인증과 실제 로그 조회 검증을 구분한다.
- 모델이 없는 사용자의 비 AI 기능 이용과 기존 작업 조회를 차단하지 않는다. 첫 작업은 기존 생성 화면에서 사용자가 직접 실행한다.

### 3단계: 문서와 회귀 검증

- `docs/local-development.md`, README의 최초 설정 안내를 실제 화면 순서와 맞춘다. 로그인 비밀번호, 설정 토큰, DB 비밀번호의 역할을 구분하고 실제 값은 기록하지 않는다.
- 검증은 사용자 허용 범위에서 진행한다. 현행 규칙에 따라 이번 계획 단계에서 빌드·테스트는 실행하지 않는다.
- 신규 설치 관리자 생성 경로는 기존 DB를 비우거나 비밀번호를 지우지 않고 모의 API 상태로 검증한다. 새 설치 DB 통합 검증은 별도 허용된 격리 환경에서만 수행한다.
- 구현 완료 시 당일 `docs/complete`에 수정 파일, 검증 결과, 미검증 범위를 기록한다.

## 완료 기준

- 새 설치: 기존 초기 관리자 보호를 유지하면서 언어 선택 → 관리자 설정 → 시작 안내로 연결된다.
- 기존 설치: 기존 화면·데이터·설정을 유지하고 필요할 때 시작 안내를 열 수 있다. 작업 0개만으로 최초 설치라고 단정하지 않는다.
- 환경 변수 기반 모델 설정, 모델 미설정, 잘못된 인증, timeout, DB 조회 실패, runner 미구동을 서로 다른 상태로 안내한다.
- 선택 기능을 건너뛰어도 사용할 수 있는 기능에 진입 가능하며 새로고침·재로그인으로 안내를 이어갈 수 있다.
- 외부 요청과 작업·샘플 생성은 자동으로 발생하지 않는다. 비밀 값이 URL·브라우저 상태·안내 문구에 복제되지 않는다.
- 5개 언어, 모바일 화면, 키보드 탐색, 재방문 및 설정 변경 후 상태 갱신을 확인한다.
- DB 스키마 추가·초기화·리셋 없이 구현한다. 관리자 및 연결 저장은 기존 API가 담당한다.

## 이번 검토에서 실제 확인한 범위

후속 구현은 [온보딩·OpenRouter 완료 기록](../complete/2026-10-23-onboarding-openrouter.md)에 정리했다.
ChatGPT 구독 연결은 [OAuth 완료 기록](../complete/2026-10-23-chatgpt-oauth.md)에 별도로 기록했다.
아래는 최초 계획 시점의 확인 기록이며 후속 구현의 동작 검증 결과는 아니다.

- `GET http://localhost:8787/api/health`: ok=true, version=1.0.0-dev.
- `GET http://localhost:8787/api/auth/status`: initialized=true, setup_token_required=false.
- 인증 후 연결 설정의 실제 값·모델·Splunk 동작은 조회하거나 시험하지 않았다.
- 앱 코드 변경, DB 변경, 빌드·테스트, 프로세스 시작·재시작, 외부 연결은 수행하지 않았다. 계획 문서만 추가했다.
