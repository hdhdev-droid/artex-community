# 2026-10-27 로컬 Docker v1.0.0 정식 릴리스 전환

## 요청과 결과

- 기존 로컬 Docker를 공개된 ARTEX Community v1.0.0 이미지로 교체했다. 접속 주소는 계속 **http://localhost:5173**이며 http://localhost:8787에서도 같은 화면을 제공한다.
- 기존 DB·업로드·JWT·ChatGPT 인증 정보를 유지했다. 사용자 승인 범위의 정상 앱 기동 처리를 수행했으며, DB 초기화·리셋·수동 데이터 변경·볼륨 삭제는 하지 않았다.
- 실제 OAuth 로그인, 모델 목록 갱신·LLM 요청, Splunk 조회, 진단 실행은 하지 않았다. 외부 Chrome의 기존 로그인 세션으로 로컬 화면을 확인했다.

## 적용한 이미지와 실행 구성

- 공개 이미지: `ghcr.io/hdhdev-droid/artex-community:v1.0.0`
- 고정 다이제스트: `sha256:93f525020c73f19bca050584c752920969173de7f3324ec2efe27d46be28f41a`
- 실행 환경: Linux amd64, Docker Compose v5.5.1. 실제 실행 이미지 ID와 공개 다이제스트가 일치한다. 바이너리와 `/api/health`가 모두 `1.0.0`을 반환한다.
- 개발용 web 컨테이너는 중지하고, 정식 이미지에 포함된 화면을 기존 5173 포트로 제공한다. backend만 재생성했으며 PostgreSQL과 진단 runner의 컨테이너 ID는 전환 전후 동일하다.
- 기존 `runtime` 볼륨을 `/app/auth`로 연결했다. 기존 인증 파일을 그대로 사용하면서 개발 바이너리가 정식 이미지의 `/app/artex`를 가리지 않게 한다. `pgdata`와 `data` 볼륨도 유지한다.
- 진단 runner는 기존 로컬 개발 이미지를 유지한다. 이번 교체 대상인 앱·내장 UI와 구분하며 runner의 실제 스캔을 수행한 것은 아니다.

## 확인 중 발견하여 수정한 문제

기존 DB의 Python 실행 경로는 `/usr/bin/python3`이지만 정식 이미지에는 `/usr/local/bin/python3`이 있었다. 그대로 사용하면 사용자 Python 도구 실행이 실패할 수 있어, 로컬 시작 스크립트에서 기존 경로가 없는 경우 이미지의 Python을 가리키는 링크를 만든다. DB의 사용자 설정은 변경하지 않았다. 수정 후 앱을 재시작했고 기존 경로에서 `Python 3.12.15` 실행을 확인했다.

## 보존 검증

- JWT 파일과 암호화된 ChatGPT 인증 파일은 전환 전후 SHA-256 비교가 일치한다. 값과 파일 내용은 출력하거나 전송하지 않았다.
- `data` 볼륨 파일 6개, 합계 111,971바이트의 경로·크기·내용 지문이 전환 전후 일치한다.
- DB 65개 테이블의 행 수·전체 행 지문을 읽기 전용 트랜잭션으로 비교했다. 62개 테이블은 완전히 일치한다. `agents` 8행과 `mcp_servers` 2행은 정상 기동에 따른 `updated_at`만 바뀌었고 다른 내용은 일치한다. `server_logs`는 두 번의 앱 기동으로 21행에서 25행으로 늘었다.
- 기존 작업 0개, LLM 프로필 1개, 설정 27개를 유지한다. 샘플·데모 데이터를 추가하지 않았다.
- 기존 브라우저에서 다시 로그인하지 않고 설정·LLM·작업 목록에 접근했다. ChatGPT 계정 선택 시 저장된 인증을 읽어 `Account connected`가 표시됐다. 이는 로컬 인증 저장소 확인이며 공급자에서 토큰의 현재 유효성을 검증한 결과는 아니다.

## 정상 동작 확인

- 5173·8787의 상태 API: HTTP 200, `ok: true`, 버전 `1.0.0`.
- 인증 없이 작업·ChatGPT 계정 API를 호출하면 HTTP 401로 차단된다.
- 설정 화면: 현재 버전 `1.0.0`, 최신 버전 `v1.0.0`, community 업데이트 저장소와 상류 기준 표시 확인.
- 기존 작업 목록, 온보딩, LLM 설정, API·소스 진단 화면의 로드 확인. 진단 서비스의 내부 상태 조회도 `ok`다.
- 확인한 화면의 브라우저 오류 0개, 마지막 기동 로그의 error/failed/fatal/panic 항목 0개, 컨테이너 자동 재시작 횟수 0회.
- Compose 설정 검사와 시작 스크립트 구문 확인을 수행했다. 로컬 프런트엔드 빌드·전체 테스트 재실행은 하지 않았으며 이미 발행된 이미지를 사용했다. 설정을 유지하기 위해 언어 저장·전환은 수행하지 않았다.
- 비교용 지문·HTTP 결과·실행 상태·최종 화면은 Git 제외 경로 `work/local-release-verification/`에 보관한다. 인증 값이나 DB 원문을 저장한 검증 자료는 없다.

## 사용 안내

- 외부 Chrome에 정식 버전 설정 화면을 남겼다. 기존 계정으로 바로 사용할 수 있다.
- 저장된 ChatGPT 모델 프로필은 기존처럼 **비활성**이다. AI 작업을 실행하려면 **LLM → ChatGPT 프로필 → Set active**를 선택한다. 이번 전환에서는 활성화 상태를 바꾸거나 외부 모델을 호출하지 않았다.
- 이후에도 정식 이미지를 유지하려면 [로컬 개발 안내](../local-development.md)의 두 Compose 파일을 함께 사용한다. 기본 개발 시작 스크립트는 소스 개발 모드로 돌아간다.
- 공개 v1.0.0 태그·이미지·릴리스 첨부물은 변경하지 않았다. 이번 로컬 실행 구성과 문서 변경은 아직 커밋·푸시하지 않았다.
