# 보고서 샘플 데이터 반영 — 2026-10-23

## 반영 내용

요청: 남은 작업을 정리하고 보고서에 샘플 데이터를 추가.
기존 DB 변경 금지 조건을 유지하여 `NEXT_PUBLIC_MOCK=1` 데모 보고서 경로만 보완했다.
일반 모드의 `/api/report` 응답과 저장된 개별 취약점 보고서, 사용자 입력·증거 원문은 변경하지 않았다.

기존 샘플은 작업 ID를 무시하고 같은 보고서를 반환했다. 본문의 총 6건과 위험도별 합계 8건도 불일치했다.
이를 기존 가상 작업 4개의 작업별 보고서로 교체했다. 건수는 현재 데모 발견 목록에서 계산하고, 참조 작업의 발견을 중복 집계하지 않는다.

| 작업 | 보고서 샘플 | 발견 수 |
| --- | --- | --- |
| `t-acme-web` | 외부 웹·내부 연계 종합 진단 | 13건: 치명적 2, 높음 6, 중간 4, 낮음 1 |
| `t-acme-api` | API 인증·인가 진단 | 3건: 높음 2, 낮음 1 |
| `t-shop-pay` | 결제·주문 흐름 중간 점검 | 1건: 중간 1 |
| `t-vpn-edge` | 발견이 등록되지 않은 완료 작업 | 0건: 안전성 보증과 구분 |

각 문서에는 샘플 표시, 개요, 범위·목표 원문, 위험도·검증 상태 표, 발견별 증거 원문, 개선·재검증 계획, 한계를 포함했다.
검토 대기를 확인 완료로 바꾸거나 권고 조치를 수행 완료로 표시하지 않는다.
한국어로 작성한 샘플 문서이며 화면 언어를 변경해도 본문과 인용 원문을 자동 재작성하지 않는다.

## 수정 파일

- `web/src/lib/mock/reports.ts`: 4개 보고서 시나리오와 Markdown 구성. 작업별 발견 필터링·건수 계산. 증거는 코드 블록으로 감싸 원문의 HTML·Markdown 문자를 그대로 표시한다. 알 수 없는 작업은 다른 작업 보고서 대신 빈 결과를 반환한다.
- `web/src/lib/mock/handler.ts`: 데모의 현재 작업·발견 상태를 보고서에 전달하는 `mockReport` 추가.
- `web/src/lib/api.ts`: 기존 고정 보고서 제거, 데모 보고서 함수 연결. 실제 서버 요청은 유지.
- `docs/examples/reports/t-acme-web.md`, `t-acme-api.md`, `t-shop-pay.md`, `t-vpn-edge.md`: 동일 구성 함수로 생성한 바로 읽을 수 있는 보고서 샘플.

## 확인 결과와 사용 위치

실행 중인 로컬 web 컨테이너의 설치된 TypeScript 도구를 이용해 순수 데모 데이터에서 보고서 문서 4개를 생성했다.
DB 접근·데이터 삽입, 외부 호출, 신규 프로세스 실행, 프런트엔드 빌드·테스트는 하지 않았다. 변경 파일의 `git diff --check`를 확인했다.
이전 언어 검증의 테스트 통과 결과를 이번 샘플 변경의 빌드·테스트 통과로 간주하지 않는다.

데모 모드에서 **작업 → 해당 작업 상세 → 보고서**로 확인한다.
일반 모드로 실행 중인 개발 서버의 실제 작업 DB에 샘플을 넣은 것은 아니다.
바로 확인할 수 있도록 `docs/examples/reports/`에 문서도 저장했다. 실제 보고서 탭의 렌더링·복사 재검증은 이번 작업에서 실행하지 않았다.

## 남은 작업

필수 구현 누락으로 확인된 항목과 미실행 검증을 구분한다. 기존 언어 감사의 로컬 빌드·DB 없는 테스트·5개 언어 화면 전환은 완료 기록을 참조한다.

1. 실제 DB에 언어 저장 후 다른 브라우저의 진입·복귀 동기화 확인, 최신 변경에 대한 DB 연동 회귀 테스트.
2. 실제 LLM·Splunk·알림 서비스 연동 검증. 외부 연결 금지에 따라 미실행.
3. 실제 원본 데이터 이전. 샘플 DB 복원 검증 이력은 있지만 실제 업로드 파일·암호화 연결 정보까지 이전한 결과가 아님. 현재 사용자 선택으로 제외.
4. 전체 기능 화면·모바일 크기의 전수 확인. 샘플 보고서 탭은 아래 후속 검증을 완료했으며, 실제 클립보드 본문 일치 확인은 남아 있다.

AWS 실습 환경은 삭제 요청에 따라 제거된 범위이므로 후속 작업에 포함하지 않는다.

## 후속 로컬 연결·테스트 — 2026-10-23

사용자의 후속 로컬 테스트 요청에 따라 위 최초 반영 때 미실행했던 빌드·테스트·보고서 화면 검증을 진행했다. DB 변경·외부 연결 금지는 유지했다.

### 추가 수정

- `web/src/lib/mock/reports.ts`: `constructor`, `toString`, `__proto__`처럼 객체 상속 속성과 같은 작업 ID에서 샘플 조회가 잘못되어 예외가 발생하는 문제를 `Object.hasOwn` 확인으로 수정했다.
- `web/src/lib/mock/reports.test.ts`: 실제 데모 `api.report` 경로의 작업별 건수·발견 분리·네트워크 미호출, 기본/미등록 작업, 증거 원문·입력 보존, 백틱 포함 증거, 상속 속성 이름 회귀 검증 7개를 추가했다.
- 이 완료 문서에 검증 결과와 실행 위치·한계를 기록했다. 실제 API 및 DB 구현은 변경하지 않았다.

### 실행 결과

- 기존 로컬 Node 이미지와 설치된 의존성만 사용한 `--network none`, `--pull=never` 컨테이너에서 수행. 저장소는 읽기 전용으로 연결하고 별도 컨테이너 작업 디렉터리에서 실행했다. 환경 파일은 복사하지 않았다.
- 프런트엔드 Vitest: **9개 파일, 33개 테스트 통과**. 첫 실행에서 위 작업 ID 경계 사례가 실패하여 수정 후 전체 재실행했다.
- `NEXT_PUBLIC_MOCK=1`, `NEXT_EXPORT=1` 프로덕션 정적 빌드: **성공**, TypeScript 검사 및 36개 페이지 생성 완료. 정적 내보내기에서 서버 API·미들웨어가 비활성화된다는 Next.js 안내는 해당 검증 모드의 의도된 제한이다.
- Chrome 실제 보고서 탭: `t-acme-web` 13건, `t-acme-api` 3건, `t-shop-pay` 1건, `t-vpn-edge` 0건 및 작업 ID·위험도별 건수 확인. 웹/결제/경계 작업 상세 발견 수도 각각 13/1/0으로 일치했다.
- 웹 보고서의 증거 코드 블록 13개가 샘플 문서의 증거 원문과 모두 일치했다(끝 줄바꿈 차이 제외). `<script>` 문자열은 코드 텍스트로 남았고 팝업이 발생하지 않았다.
- API 보고서 복사 버튼에서 `Markdown copied` 성공 표시 확인. 자동화 도구의 가상 클립보드가 빈 값으로 반환되고 붙여넣기를 지원하지 않아 **실제 클립보드 본문 전체 일치는 미검증**이다. 이 도구 한계를 앱 결함으로 단정하지 않았다.
- 해당 탭에서 수집한 브라우저 오류·경고 없음.

### 로컬 확인 위치와 운영 범위

- 미리보기: `http://localhost:5183/function/tasks/detail/?id=t-acme-web` → **Report** 탭. 작업 목록에서 나머지 샘플도 선택할 수 있다.
- 정적 샘플 서버는 localhost에만 바인딩하며 `/api/`를 차단한다. 브라우저 CSP로 외부 연결도 제한한다. **일반 개발 서버와 실제 DB에 샘플을 삽입하거나 연결한 결과는 아니다.**
- 현재 미리보기는 `work/report-validation/serve.py`로 실행 중이다. 종료 후 재확인은 저장된 정적 산출물이 있는 상태에서 `python work/report-validation/serve.py`로 가능하다. 이 작업 폴더는 Git 추적 대상이 아니다.
- 기존 backend/web/postgres/offensive-runner 컨테이너는 재시작하거나 변경하지 않았다. DB 접근·변경, 외부 LLM/Splunk 호출, 실제 대상 진단은 수행하지 않았다.
- 로그·화면 증거: `work/report-validation/tests-final.log`, `build-final.log`, `api-report.png`, `web-report.png`. 테스트와 빌드 종료 코드는 각각 0.
