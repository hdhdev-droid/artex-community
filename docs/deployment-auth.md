# 운영 인증 정보 보존과 업데이트

## 저장 위치

- 운영 Compose: `./auth` → `/app/auth` (`ARTEX_AUTH_DIR`). `jwt.key`와 `chatgpt-oauth/credentials.enc`를 함께 보존합니다.
- 로컬 개발 Compose: 기존 `runtime` 볼륨의 `/app`을 유지합니다. 저장된 로그인과 인증 정보를 옮기거나 초기화할 필요가 없습니다.
- 독립 실행 파일: 기본값은 실행 파일이 있는 디렉터리입니다. 경로를 바꾸려면 `ARTEX_AUTH_DIR`를 지정하고 기존 인증 파일 두 개를 먼저 옮깁니다.
- DB는 `pgdata`, 업로드·진단 결과는 `data`에 있습니다. 인증 파일을 탐색 가능한 `data` 아래에 두면 기동을 거부합니다.

JWT 파일이 손상되었거나 OAuth 파일만 남아 있으면 새 키를 생성하지 않고 기동을 중단합니다. 올바른 JWT와 암호화 파일 쌍을 복원해야 합니다. 비밀번호를 바꾼 경우에는 기존 정책대로 로그인 세션이 무효화됩니다.

## 기존 운영 컨테이너에서 최초 1회 이전

**기존 컨테이너를 삭제하거나 재생성하기 전에 실행합니다.** 이전 버전은 `/app`의 인증 파일을 컨테이너 쓰기 계층에 보관했으므로 새 볼륨만 추가하면 보존되지 않습니다. 아래 작업은 서비스 중단 시간이 필요하며 운영자가 수행합니다. `docker compose down`, `down -v`, 볼륨 삭제는 사용하지 않습니다.

1. 프로젝트 폴더에서 현재 컨테이너 이름을 `docker compose ps artex`로 확인하고 메모합니다. 데이터베이스와 `data`는 별도로 백업합니다. 진행 중인 작업이 끝난 뒤 `docker compose stop artex`로 앱만 중지합니다.
2. Python 3.9 이상과 Docker CLI로 기존 인증 정보를 점검하고 복사합니다. `<기존컨테이너>`를 실제 이름으로 바꿉니다.

   ```text
   python scripts/migrate-docker-auth.py --container <기존컨테이너> --output auth --check
   python scripts/migrate-docker-auth.py --container <기존컨테이너> --output auth
   ```

   파일 내용은 출력하지 않습니다. 기존 파일을 지우지 않으며, 목적지에 다른 인증 정보가 있으면 덮어쓰지 않고 중단합니다. 동일 파일로 재실행할 수 있습니다. 기존 경로가 `/app`이 아니면 `--source-dir`를 지정합니다. Windows에서는 `auth` 폴더 ACL도 서비스 관리자만 읽도록 제한합니다.
3. 두 명령이 성공한 후 새 Compose와 `ARTEX_TAG=v1.0.0`을 적용하고 `docker compose up -d --no-deps artex`로 교체합니다. 이미지가 아직 발행되지 않았으면 이 단계를 실행하지 않습니다.
4. 기존 비밀번호로 로그인하고 ChatGPT 연결 상태·모델 조회를 확인합니다. 로그에 인증 복원 오류가 있으면 새 로그인이나 키 재생성을 시도하지 말고 원래 인증 파일 쌍을 복원합니다.

이미 삭제한 컨테이너에서 인증 파일을 복구할 수는 없습니다. 백업이 없다면 새 설치로 로그인·ChatGPT 연결을 다시 해야 합니다. DB에 저장된 일반 API 설정과 OAuth 인증 파일은 별도입니다.

## 백업·복원과 롤백

인증 백업은 앱을 중지한 상태에서 `auth` 디렉터리 전체를 함께 보관합니다. 파일마다 다른 시점의 사본을 섞거나 DB만 복원하지 않습니다. 백업은 저장소·Docker 빌드 문맥에 포함하지 않으며 공유하거나 로그에 출력하지 않습니다. PostgreSQL과 `data`도 같은 점검 시점에 별도로 보관합니다.

같은 설치의 컨테이너 교체·호스트 이전에는 동일한 인증 디렉터리를 연결합니다. 하나의 인증 디렉터리를 여러 활성 인스턴스에 공유하면 갱신 토큰이 충돌할 수 있으므로 단일 앱 인스턴스로 운영합니다. 복원 뒤 제공자가 이미 폐기한 갱신 토큰은 재로그인이 필요할 수 있습니다.

Docker 롤백은 이전 이미지 태그로 앱만 교체하고 인증·데이터 마운트를 그대로 유지합니다. `ARTEX_AUTH_DIR`를 지원하지 않는 구버전으로 돌아갈 때는 앱을 중지하고 원래 `/app/jwt.key`, `/app/chatgpt-oauth` 위치를 별도 마운트로 제공해야 합니다. 실행 파일 롤백은 DB 롤백이 아니므로 스키마 호환성은 별도 확인합니다. 내부 자동 업데이트보다 버전이 고정된 이미지 교체를 권장합니다.
