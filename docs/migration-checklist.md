# 기존 설치 이전 절차

이번 작업에서는 실제 원본 설치의 DB·파일·인증 정보를 이전하지 않았다.
사용자 요청에 따라 절차와 임시 DB의 복원 검증만 준비했다.

## 준비

1. 원본·대상 설치의 버전과 기능 차이를 기록한다. 원본의 DB 주소나 인증 값은 문서·명령 출력에 남기지 않는다.
2. 이전 중 생성·수정되는 작업을 멈출 시간을 정한다. DB와 파일 저장소는 같은 시점의 일관된 사본이어야 한다.
3. 원본 PostgreSQL은 사용자에게 승인받은 읽기 전용 백업만 수행한다.
   대상은 기존 DB가 아닌 새로 만든 별도의 복원 환경을 사용한다.
4. DB 덤프 외에 진단 업로드·실행 결과, 작업 파일, 트래픽 증거 및 보관 파일의 저장 위치와 총 파일 수를 확인한다.
   임의로 원본 디렉터리를 이동·삭제하거나 대상 디렉터리에 덮어쓰지 않는다.
5. 설치 키는 출력·채팅·내보내기·복사하지 않는다.
   다른 설치의 키로 암호화된 Splunk 연결은 대상에서 사용자가 인증 정보를 다시 입력한다.
   모델·외부 서비스 연결도 대상 설치에서 사용자가 설정한다.

## 별도 복원 환경에서 확인할 사항

- PostgreSQL 버전과 확장 호환성을 확인한 뒤 덤프를 복원한다.
- 테이블·행 수 및 내용을 확인한다. 파일 저장소의 상대 경로·크기·해시를 대조하되 파일 본문이나 비밀 값은 출력하지 않는다.
- 후보 검토의 저장·이어하기, 방어 실행, 독립 사건·조사, Closed-loop, 작업 보관·복원, 증거 다운로드를 확인한다.
- 이전 중 실행 상태였던 조사·작업이 재시작 시 어떻게 처리되는지 확인한다.
- 최초 설정·로그인·세션 무효화는 대상 설치의 인증 정책을 따른다.
- 외부 연결·진단 실행은 별도 승인 후 수행한다. 데이터 복원만으로 외부 조회나 공격을 시작하지 않는다.
- 검증이 끝날 때까지 원본과 백업은 보존한다. 운영 전환은 별도 승인 단계이다.

## 이번 로컬 검증

`scripts/Test-Dev.ps1`은 앱 DB와 분리된 `postgres-test`에서 관련 테스트를 실행한다.
이어 `scripts/check-dev-restore.sh`가 테스트로 만든 `artex_test_db`를 백업하고
새 `artex_restore_check_<시각>` DB로 복원한다. 모든 public 테이블의 행 수와 정렬된 행 내용의
지문을 비교하며, 원본 행 내용은 콘솔에 출력하지 않는다.

이 절차는 실제 원본 설치의 데이터·업로드 파일·암호화 인증 정보 이전 성공을 의미하지 않는다.
작업 보관 파일의 과거 형식 호환과 방어·조사 이력 보존은 별도 DB 테스트로 검증한다.
